# LogBridge Exhaustive Decision Search

This example enumerates every finite path generated by `LogBridgeDecisionGenerator`
and minimizes the total completion time (makespan).

## Decision semantics

- `ControlDecision(target_model, xevent)` queues an external input for a target model. In this example, `target_model` is the hierarchical model path and `xevent` is the input-port name `"?go"`.
- `NoControl()` explicitly queues no external input and advances the branch to the next DEVS event.
- If a Wait decision cannot advance time and leaves the complete snapshot unchanged,
  the branch is classified as a deadlock leaf.
- A branch stops at the next state with available decisions, at full completion,
  at deadlock, or at the configured simulation time bound.

The search is exhaustive over the decisions emitted by `LogBridgeDecisionGenerator`:
one bridge-entry alternative for each waiting source Load, plus Wait. It does not
enumerate control actions that the generator does not provide.

## Objective

A path is feasible only when both destination Loads have reached their waiting
phase, both source Loads are idle, and the bridge is idle.

The objective is the absolute simulation time at which this terminal condition
is first reached:

```text
makespan = final completion time
```

Incomplete and deadlocked leaves receive `None` and are excluded from the
optimization.

## Run

From the repository root:

```python
from examples.LogBridge.LoadPassive_LogBridge import run_exhaustive_optimization

result = run_exhaustive_optimization()
```

The optimization report includes each optimal path and its Snapshot details by
default. Pass `include_snapshot_details=False` to print only the generic Node/Edge
path. For other DecisionTree uses, `SnapshotFormatter` can be passed as the
`node_formatter` to `format_path()` or `print_path()`.

Or call the search function directly:

```python
from examples.LogBridge.LoadPassive_LogBridge import make_model
from examples.LogBridge.exhaustive_search import run_logbridge_exhaustive_search

result = run_logbridge_exhaustive_search(make_model())

print(result.node_count)
print(result.leaf_count)
print(result.best_cost)
print(result.optimal_paths())
```

## Expected result for the current model parameters

- Decision-tree nodes: 18
- Terminal paths: 10
- Completed paths: 6
- Deadlocked/incomplete paths: 4
- Minimum makespan: approximately 84.444444
- Number of optimal paths: 2

The two optimal decision sequences are:

1. `Control(Load_LogBridge.L11, ?go)` then `Control(Load_LogBridge.L21, ?go)`
2. `NoControl`, `Control(Load_LogBridge.L21, ?go)`, then `Control(Load_LogBridge.L11, ?go)`

The two schedules tie because the Loads have different travel times and their
destination-side travel can overlap with the next bridge crossing.

## Replay validation

To replay every terminal path and compare each generated Snapshot with the
corresponding Snapshot stored in the DecisionTree, run from the repository root:

```bash
python -m examples.LogBridge.validate_paths
```

The search and validator must share the same `TESEngin` model instance because
Snapshots are bound to the identities of the model objects that created them.
The example therefore passes the engine into `run_logbridge_exhaustive_search`
and reuses it for `DecisionPathValidator`.

The validator now reports four layers of checks for every terminal path:

- Snapshot continuity immediately before each Decision (`pre` count)
- Snapshot equality immediately after each Decision (`post` count)
- Final Snapshot equality and terminal classification (`COMPLETED`, `DEADLOCK`, or `TIME_LIMIT`)
- Makespan equality between the stored terminal Snapshot and the replayed terminal Snapshot

A successful report shows `Final state: MATCH`, identical terminal classifications,
and identical makespan values. The terminal classifier and cost evaluator are
provided by the example because terminal semantics and objective values belong to
the application domain, not to the SOCS Core validator.
